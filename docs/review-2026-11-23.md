## Decisions needed

Answered by the owner on 2026-11-23: D1 one FIFO worker; D2 plain above 2 MB, refuse above
20 MB; D3 the same project reloads, a different one asks first; D4 pure functions now, a WebKit
harness as its own later PR; D5 `npx` lint and format in CI with no `package.json`; D6 follow
the symlink and keep the mode; D7 hide nested repositories; D8 split build and sign. Every item
is `fix` except CI6, CI8, CS9 and MD19, deferred: setup work or no measured cost.

The options as they were weighed:

- **D1. Request worker model** (SH1). Proposal: one FIFO worker thread owns `Site` and answers
  through wry's `with_asynchronous_custom_protocol`; page assets are still answered inline. One
  worker keeps request order, which `open` followed by `api/repo` relies on. A pool would let a
  slow `changes` call stop blocking a file click, but needs ordering rules.
- **D2. Large files** (MD1). Proposal: above 2 MB, serve the file as plain lines with no
  highlighting; above 20 MB, refuse with an error naming the size. Alternative: one limit,
  refuse above it.
- **D3. Opening a project during a live run** (SH2). The same project: keep the runner and
  reload (no question). A different project: proposal is a 409 that the page turns into a
  confirm ("A run is in progress. Stop it and open X?"). Alternative: keep today's behavior
  (kill the run) for a different project.
- **D4. Page end-to-end tests** (JS22, and the tests for JS1 to JS9). The page has no npm
  packages by design. Options:
  1. Extract every decision (redraw keys, Esc routing, reveal-on-refresh) into pure functions
     and unit-test them with `node --test`. No new dependency. Does not catch a click lost to a
     replaced node.
  2. Add a WebKit end-to-end harness (Playwright WebKit against the served `ui/` with a fake
     API). Catches the click bugs; adds an npm dev dependency and a browser download to CI.
  3. Drive the real app through wry's test hooks. No new dependency; the most work.

  Proposal: 1 now, 2 as its own PR if the owner accepts an npm dev dependency.
- **D5. JS lint and format** (JS20). Proposal: run `npx oxlint` and `npx oxfmt --check` in CI
  with exact versions and no committed `package.json`. Alternative: none, keep the page
  dependency-free.
- **D6. Config symlinks** (MD4). Proposal: follow the symlink and write beside the real file,
  keeping its mode. Alternative: refuse to save a symlinked file with an error.
- **D7. Nested repositories and submodules** (MD2). Proposal: hide them from the file list.
  Alternative: show them as non-openable rows.
- **D8. Release pipeline** (CI1, CI2). Proposal: a `build` job with no secrets uploads the
  unsigned `.app`; a `sign` job in the `release` environment downloads it, signs, notarizes and
  publishes, and first checks that the tag's commit is on `main` and that its CI passed.

## Implementation plan

Principles for the order:

- Gate first, so every later PR is checked by the doc step.
- Bugs before structure, because they are what users hit. Bug PRs are grouped by file set, so
  they can run in parallel worktrees without conflicts.
- Pure moves (file splits) come after the bug fixes that touch the same files, and each is its
  own PR with no behavior change, so the review is a move check.
- Every PR follows AGENTS.md: tests end to end through `Site::respond`, the CLI, or
  `node --test` first; each test names the bug it catches; the code is broken once to see the
  test fail; `cargo mutants` over the changed code before `gh pr ready`, result posted on the PR.
  20 or more lines of Rust need a `rust-style-reviewer` run.

Parallel tracks are marked: PR 2, 3, 4 and 5 touch disjoint files and can run at once.
